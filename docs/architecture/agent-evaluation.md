# Product Intelligence Agent Evaluation

## 目标

Agent Eval 回答的不是“LLM 请求有没有成功”，而是“Agent 是否完成了产品经理需要的判断”。运行稳定性继续由来源可用率、重试、失败批次和耗时监控；效果质量由固定历史真实情报与人工标签单独评估。

当前评测用于作品集级离线回归，不代表真实线上用户任务完成率。生产化仍需要更多样本、双人标注一致性、真实用户反馈、成本与延迟趋势。

## 固定数据集

`data/agent/evaluation/cases.json` 只引用 `data/intelligence` 中已经保存的真实公开情报。每条样本包含：

- 可接受的 PM 价值类型；
- 人工判断的合理机会分区间；
- 是否应进入自动深度分析；
- 中文概述必须覆盖的关键事实组；
- 人工标注理由。

数据集版本变化后不得直接与旧版本指标比较。调整标签必须回到原始标题、摘要、页面公开描述和 URL 核对，不能根据模型输出反向修改标准答案。

如果发现评测标签本身引用了错误数据，旧结果标记为 `invalid` 并保留归因说明，质量看板和版本对比自动排除该结果，而不是静默删除历史记录。

## 指标定义

| 指标 | 定义 | 作用 |
| --- | --- | --- |
| 任务完成率 | 返回完整候选的样本数 / 总样本数 | 主要结果指标，判断 Agent 是否完成批量任务 |
| 结构化输出成功率 | 中文概述、五维评分与机会分均合法的样本数 / 总样本数 | 运行质量护栏 |
| 事实覆盖率 | 中文概述命中的人工关键事实组 / 全部关键事实组 | 判断概述是否真正说明“是什么、做什么、发生了什么” |
| PM 分类准确率 | PM 价值类型落入人工允许集合的样本数 / 总样本数 | 判断产品视角分类能力 |
| 机会分一致率 | 机会分落入人工合理区间的样本数 / 总样本数 | 判断排序与评分策略 |
| 深度分析决策一致率 | 70 分阈值决策与人工标注一致的样本数 / 总样本数 | 判断自动执行边界 |
| 人工修订率 | 至少出现一个效果问题的样本数 / 总样本数 | 越低越好，用于估计人工复核负担 |

综合质量分按任务完成 15%、结构化输出 15%、事实覆盖 25%、PM 分类 15%、机会分一致 15%、深度分析决策一致 15% 加权。综合分只用于版本回归，不能掩盖单项指标下降。

## Bad Case 根因

| 根因 | 典型问题 | 主要改进杠杆 |
| --- | --- | --- |
| 运行链路 | 样本缺失、结构化字段不完整 | Tool 约束、JSON Schema、异常恢复 |
| Prompt | 中文概述遗漏来源关键事实 | 指令、上下文组织、示例 |
| 分类策略 | PM 价值类型与人工判断不一致 | 分类定义、边界案例、few-shot |
| 评分策略 | 机会分超出人工合理区间 | 评分 rubric、权重、证据惩罚 |
| 决策阈值 | 自动深度分析判断不一致 | 阈值、类别差异化策略、人工门控 |

## 运行与发布

```bash
pnpm agent:eval
```

脚本使用隔离 Repository 运行固定数据集，不写入 `data/agent/runs.json`，只向 `data/agent/evaluation/results.json` 追加版本化结果。GitHub Actions 的 `SignalFlow Agent Evaluation` 只允许手动触发，避免每天重复消耗固定集 LLM 配额。

建议版本发布门槛：任务完成率和结构化输出成功率不得回退；综合质量不得低于同数据集上一版本；深度分析决策一致率下降超过 5 个百分点时停止升级并复核 Bad Case。

## 当前基线

固定集 `2026-08-17-v1` 共 10 条真实历史情报：

- 综合质量：91%（v4 基线为 85%）
- 任务完成率：100%
- 结构化输出成功率：100%
- 事实覆盖率：100%（v4 基线为 86%）
- PM 分类准确率：90%
- 机会分一致率：70%
- 深度分析决策一致率：80%（v4 基线为 70%）
- 人工修订率：30%（v4 基线为 50%，越低越好）

第一轮 Bad Case 显示旧的 generated 中文草稿会污染事实判断，因此 v5 改为原始标题、摘要和页面描述优先，只允许已审校中文辅助理解。同一固定集复跑后事实覆盖与深度分析决策均提升；当前主要改进空间仍位于机会分 calibration。
